# package.json の事前知識

VSCodeが拡張機能を実行する際、最初に読み込まれるのが`package.json`です。

`package.json`では、以下のような項目を設定します。

- 拡張機能の名前
- VSCodeの対応バージョン
- 有効化タイミング
- 機能をコマンドに割り当てる
- 機能をメニューに割り当てる
...

項目が非常に多いですが、すぐに覚えるべきものは限られています。

事前知識として、拡張機能開発のイメージをつかむために、一部説明します。

---

## package.json の役割と基本構造

拡張機能と同様に、npm（node）プロジェクトにも`package.json`が必須級です。

一般的な拡張機能開発では、1つの`package.json`でnpmとVSCodeの両方に影響します。

> npm用の`package.json`に、拡張機能特有のフィールド（`engines`, `categories`, `contributes`...）を追加したような内容になっています。

```json
// 一例
{
  "name": "vscode-extension-sample",
  "displayName": "vscode-extension-sample",
  "description": "拡張機能の説明文",
  "version": "0.0.1",
  "engines": {
    "vscode": "^1.140.0"
  },
  "categories": [
    "Other"
  ],
  "activationEvents": [],
  "main": "./out/extension.js",
  "contributes": {},
  "scripts": {}
}
```

## 主要なフィールドの意味

| | |
| --- | --- |
| name | 拡張機能の一意な名前（識別子）。拡張機能を公開する際などに使われます（ケバブケースが推奨） |
| displayName | 拡張機能マーケットプレイスや設定画面でユーザーに表示される名前です |
| version | 拡張機能の現在のバージョン（0.0.1など）を指定します |
| engines | この拡張機能が動作するために必要なVSCodeの最小バージョンを指定します（例: "vscode": "^1.140.0"） |
| categories | マーケットプレイスでの検索性を高めるためのカテゴリ（Other, Formatting, Snippets, Linters など）を指定します |
| activationEvents | 拡張機能をどのタイミングで有効化させるか指定します（特定のコマンドが実行された時など） |
| main | 拡張機能のエントリーポイントとなるJavaScriptファイルへのパスを指定します（./dist/extension.js など） |

## package.json と宣言的定義

VSCodeの拡張機能は、大きく分けて以下の2つで構成されます。

| | |
| :---: | --- |
| **宣言的定義** <br/> (package.json) | 「設定項目（Configuration）」や「コマンド」「メニュー」「ショートカットキー」など、UIやVSCodeに登録する静的な定義を行います |
| **プログラム** <br/> (extension.ts) | ユーザーがコマンドを実行した際の実際の処理や、設定値が変更されたときのイベント処理などを実装します |

### 「宣言的定義」は必須です

拡張機能の有効化タイミングや、コマンドに登録するのかメニューに登録するのかなど、拡張機能を使用可能にするために必須です。

### 「プログラム」は必要でないこともあります

言語サポートやキーバインド拡張機能など、一部の拡張機能ではプログラムが不要になります。

ファイルを読み込む・パネルを開くなど、動的操作が必要な拡張機能ではプログラムが必須になります。
